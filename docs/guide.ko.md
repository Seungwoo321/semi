# Semi 사용 가이드

Semi는 Slack에서 로컬 Codex·Claude Code 세션에 요청을 전달하고 결과를 받는 프로그램입니다. 사용자는 자신의 Slack 앱을 설치하고 Mac에서 Semi를 실행합니다. Slack 앱만 설치하면 예약과 대화가 동작하지 않습니다. Mac이 켜져 있고 Semi와 대상 세션이 실행 중이어야 합니다. Slack 데스크톱 앱은 열어 둘 필요가 없습니다.

## 처음 설치하기

[README 설치 절차](../README.md#install-your-slack-app)를 따라 앱 생성, 토큰 설정, 실행을 완료하세요. Node.js 24 이상과 pnpm 12.15.0을 사용합니다. pnpm 설치는 [공식 안내](https://pnpm.io/installation)를 따릅니다.

```sh
git clone https://github.com/Seungwoo321/semi.git
cd semi
pnpm install --frozen-lockfile
```

앱 설정과 토큰 입력을 끝낸 뒤 `pnpm start`로 연결을 확인합니다. 자동 실행을 설치할 때는 해당 전경 프로세스를 Ctrl+C로 종료한 뒤 실행하세요.

```sh
pnpm run service install
pnpm run service status
```

자동 실행이 설정된 Mac에서 `pnpm start`를 다시 실행할 필요는 없습니다. 코드 위치나 Node 설치 경로가 바뀌면 서비스를 다시 설치하세요.

## 실제 코딩 세션 연결하기

1. Orca 또는 cmux의 로컬 터미널에서 Codex나 Claude Code를 실행합니다. 해당 터미널 앱의 에이전트 상태 연동이 활성화되어 있어야 합니다.
2. Slack에서 본인의 `<Slack 사용자 이름>-semi` 앱과 DM을 엽니다.
3. `/semi target`을 입력합니다.
4. 목록의 터미널 앱, 에이전트, 작업 폴더와 식별자를 확인하고 원하는 세션을 선택합니다.
5. DM에 `현재 작업현황 보고`처럼 요청을 보냅니다.

별도 Semi 스킬을 각 에이전트에 설치하거나 Slack 토큰을 대화창에 붙여 넣을 필요는 없습니다. Semi가 작업 파일과 결과 전송 명령을 에이전트에 전달합니다. 실제 작업은 선택한 세션의 문맥과 권한으로 수행됩니다.

처음 DM을 보내면 세션 선택 버튼이 나타납니다. 버튼으로 세션을 선택하면 처음 보낸 요청도 전달됩니다. `/semi target`으로 대상만 선택한 경우에는 그 뒤 새 요청을 보내세요.

## DM과 스레드

- 새 DM은 현재 선택한 세션으로 전달됩니다.
- 아직 세션과 연결되지 않은 DM 스레드도 현재 선택한 세션으로 연결됩니다.
- 한 번 연결된 스레드는 원래 세션을 유지합니다. 이후 `/semi target`을 변경해도 기존 스레드의 대상은 바뀌지 않습니다.
- 보고에 답하려면 해당 보고의 스레드에 답장하세요. 채널의 일반 메시지는 에이전트 요청으로 처리하지 않습니다.
- 요청 접수와 작업 완료는 다릅니다. 에이전트가 작업 중이면 입력을 덮어쓰지 않고 쉬는 상태가 될 때까지 기다립니다. 지금 대화 중인 세션을 선택했다면 그 세션의 현재 턴이 끝난 뒤 요청이 전달됩니다.

## 30분마다 보고받기

1. Slack에서 `/semi new`를 입력합니다.
2. 예약 이름, 간격 `30`분, 실행할 프롬프트를 입력합니다.
3. Orca·cmux의 세션을 하나 이상 선택합니다. 여러 세션을 함께 선택할 수 있습니다.
4. 결과 위치를 선택하고 저장합니다. 비워 두면 기본 위치인 봇 DM을 사용합니다.

예시 프롬프트:

> 현재 세션의 완료한 작업, 진행 중인 작업, 막힌 점, 다음 작업을 한국어로 보고하세요. 보고를 위해 코드를 수정하지 마세요.

예약은 저장한 시점에서 설정 간격이 지난 뒤 처음 실행됩니다. 예약 생성과 DM 대상 선택은 별개입니다. `/semi target`만 실행해도 30분 예약이 자동으로 생기는 것은 아닙니다.

세션별 채널 설정이 예약 채널보다 우선하고, 예약 채널이 봇 기본 위치보다 우선합니다. 채널로 보고받으려면 그 채널에 Semi 앱을 추가하세요. 설치는 워크스페이스 단위이며 모든 채널에 자동으로 참여하지 않습니다.

`/semi list`로 예약 ID를 확인하고 `/semi edit ID`, `/semi pause ID`, `/semi resume ID`, `/semi delete ID`로 관리합니다. 중지·삭제는 이미 에이전트에 전달한 작업을 취소하지 않습니다.

## 응답이 없을 때

프로젝트 폴더에서 확인합니다.

```sh
pnpm run service status
node cli.js targets cmux
node cli.js targets orca
node cli.js status SCHEDULE_ID
```

- 서비스가 실행 중인지, 정식 Semi의 DM에 보냈는지 확인하세요.
- 세션 목록이 비어 있으면 대상 에이전트가 실행 중인지와 터미널 앱의 상태 연동을 확인하세요. 원격 세션이나 Orca의 구조화된 채팅 화면은 지원 대상이 아닙니다.
- 세션이 작업 중이거나 승인 입력을 기다리면 먼저 그 작업이나 승인 화면을 확인하세요. Semi는 승인 설정을 변경하지 않습니다.
- 세션을 종료하거나 새로 만들었다면 `/semi target` 또는 예약 편집으로 새 세션을 선택하세요.
- `uncertain` 상태는 입력 또는 전송 결과가 불확실하다는 뜻입니다. 터미널과 Slack을 확인한 뒤 `/semi resolve RUN_ID`로 해제하세요. 자동 재전송하지 않습니다.

로그는 `.local/profiles/personal/service.log`와 `service-error.log`입니다. 토큰과 작업 내용이 담긴 `.local` 폴더를 공개 저장소나 채팅에 올리지 마세요.

## 개인·회사 계정

개인용은 기본 `personal`, 회사용은 `SEMI_PROFILE=work`로 별도 앱·토큰·서비스를 구성합니다. [계정별 설치 안내](../README.md#personal-and-work-accounts)를 참고하세요. Slack CLI에 회사 계정으로 로그인한 것만으로 회사 Semi가 설치되지는 않습니다. 한 세션은 한 프로필에만 연결되므로 회사와 개인 작업에는 별도 세션을 사용하세요.

## 이름 변경과 제거

Slack에서 `/semi name 원하는이름`으로 봇 이름을 바꿉니다.

```sh
pnpm run service uninstall
```

위 명령은 Mac의 자동 실행만 제거하며 예약과 설정은 보존합니다. Slack 앱 삭제는 Slack 앱 관리에서 별도로 수행합니다.
